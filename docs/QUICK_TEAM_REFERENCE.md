# Quick Team Reference

## Team Overview (4-5 People)

```
Project Team
├── Product Manager (1)
├── Technical Lead (1)
├── Backend/CLI Developer (2)
└── Quality Assurance (1)
```

## Role Quick Reference

| Role | Count | Key Responsibility | Reports To |
|------|-------|-------------------|------------|
| **Product Manager** | 1 | Product vision, roadmap, stakeholder management | - |
| **Technical Lead** | 1 | Architecture, technical decisions, code quality | Product Manager (coordinates) |
| **Backend/CLI Developer** | 2 | Feature implementation, API integration | Technical Lead |
| **Quality Assurance** | 1 | Testing, quality control, validation | Works across team |

## Decision Authority

| Decision Type | Owner |
|---------------|-------|
| Product & Features | Product Manager |
| Technical & Architecture | Technical Lead |
| Implementation Details | Developers (with Tech Lead guidance) |
| Quality Standards | QA + Technical Lead |

## Key Contacts by Area

| Need Help With | Contact |
|----------------|---------|
| Feature requests, priorities | Product Manager |
| Technical questions, code review | Technical Lead |
| Implementation support | Backend Developers |
| Testing, bugs, quality issues | Quality Assurance |

## Team Size Rationale

- **Lean & Efficient**: Small enough for quick decisions
- **Adequate Coverage**: All critical functions represented  
- **Parallel Work**: 2 developers enable simultaneous feature development
- **Cost-Effective**: Optimal for MVP stage
